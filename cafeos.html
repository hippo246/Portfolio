CafeOS

Full-stack cafe POS and management system — React, Vite, Tailwind CSS

← Back to Portfolio

Project Overview

CafeOS (internally named BrewCRM) is a comprehensive cafe point-of-sale and management system built with React 19, Vite 8, and Tailwind CSS 4. It's built around a feature-module architecture with 25 modules covering daily operations (POS, Kitchen Display, Tables, Delivery), management (Menu, Inventory, Staff, CRM, Expenses, Reports), advanced features (Intelligence layer with 15 AI-assisted modules, Workflows engine, Health monitoring), and system infrastructure (Backup/Export, Print, Settings, Notifications). The system is designed for cafes, coffee shops, and quick-service restaurants that need a complete operational solution.

The system addresses key cafe pain points: fragmented POS and kitchen systems causing order errors, manual table tracking leading to poor seating efficiency, lack of real-time visibility into operations, no predictive insights for staffing and inventory, disconnected delivery platform integrations, and inability to monitor system health proactively.

Built with AI-assisted development using Kiro, Devin (formerly Windsurf), Antigravity, Trae, and Claude. My contribution involved defining business requirements across all 25 modules by studying real cafe operations, designing workflows for each operational area (POS flow, kitchen workflow, table management, delivery integration), creating the Intelligence layer with 15 AI-assisted insight modules, designing the Workflows engine for customizable automation, implementing the health monitoring system, testing functionality across different cafe scenarios, and iterating on the interface throughout development.

Problem Statement

Cafes and coffee shops face operational fragmentation as they scale:

  • Order-kitchen disconnect: Orders taken on POS don't always reach the kitchen correctly, leading to wrong drinks, missed items, and food waste
  • Inefficient seating: Manual table tracking with basic tools causes double-bookings, long wait times, and poor table turnover during peak hours
  • No operational visibility: Management cannot see real-time order counts, table status, or kitchen backlog without being physically present
  • Reactive decision-making: No predictive insights for staffing (how many baristas needed for expected rush), inventory (what to prep based on demand), or menu optimization (what items drive revenue)
  • Delivery platform chaos: Multiple delivery platforms (Zomato, Swiggy) operate separately, causing order conflicts and no unified view of delivery performance
  • System blind spots: No monitoring of system health, performance, or backup status, leading to unexpected downtime and data loss

CafeOS was built to unify all cafe operations into a single system with real-time visibility, AI-assisted insights, customizable workflows, and proactive health monitoring.

Solution Approach

The solution uses a modular architecture where each of the 25 modules is self-contained but shares state through a centralized data model. Key architectural decisions:

  • Feature-module architecture: 25 self-contained modules (Dashboard, POS, KDS, Tables, Delivery, Menu, Inventory, Staff, CRM, Expenses, Reports, Intelligence, Workflows, Health, Backup, Print, Settings, Notifications, and more) that can be enabled/disabled based on business needs
  • Intelligence layer: 15 AI-assisted insight modules covering floor operations, kitchen efficiency, menu performance, revenue trends, inventory optimization, delivery analytics, staff productivity, reservations, and purchasing patterns
  • Workflows engine: Configurable workflow builder and executor allowing cafes to automate operational processes (e.g., auto-notify kitchen when order placed, auto-clear table after payment, auto-order stock when low)
  • Health monitoring: System health dashboard monitoring performance, device status, backup health, storage capacity, and operational alerts for proactive issue detection
  • Multi-cloud backup: Backup and export system with support for multiple cloud providers (AWS S3, Azure Blob Storage, Supabase, WebDAV) for redundancy and disaster recovery
  • Deferred integrations: Delivery platform integrations (Zomato, Swiggy), cloud backup providers, and payment gateway (Razorpay) are architected and documented but intentionally deferred for real client deployment to avoid demo-specific configurations

Implemented Features

Operations

  • Dashboard — live revenue tracking for today, week, and month with real-time updates, active and completed order counts with comparison to previous periods, interactive revenue chart showing trends by time period, table status overview with color-coded availability (available, occupied, reserved), delivery platform status indicators for Zomato and Swiggy (simulated in demo, real API integration deferred for client deployment), and quick action buttons for common tasks
  • POS / Orders — menu organized by category with visual item cards, fuzzy search with autocomplete for rapid item lookup, cart with quantity controls (+/- buttons), automatic GST calculation (5% for food items), hold order functionality to pause orders and resume later, discount application (percentage or flat amount), payment modal with multiple payment methods (cash, card, UPI), order history for recent orders, and quick re-order from history
  • Kitchen Display (KDS) — live order cards displayed per table with real-time updates, urgency status indicators (Rush for time-sensitive orders, Active for normal priority, Relaxed for low priority), elapsed time timers showing how long each order has been in the kitchen, item-level notes for special requests and modifications, dietary flags (vegetarian, vegan, gluten-free, allergens), Mark Ready action for chefs to signal completion, and order completion workflow
  • Tables / Floor Plan — visual floor plan with table cards showing status, filterable by zone (Indoor, Window, Outdoor, Bar, Sofa) for easy section management, filterable by status (Available, Occupied, Reserved) for operational focus, per-table tracking showing assigned server, current order, and seating duration, Open/Close Table actions for seating and clearing tables, and table merge/split functionality for large parties
  • Delivery — delivery order management with address entry and validation, zone-based delivery fee calculation, delivery driver assignment, delivery status tracking (confirmed, preparing, out for delivery, delivered), simulated Zomato and Swiggy order management in demo mode (real API integration deferred for client deployment with architecture and documentation complete), and delivery performance analytics
  • Guest Menu / Order Tracking — customer-facing ordering page accessible at /guest/<code> where customers can browse the menu, add items to cart, place orders assigned to their table, and track order status, with stub implementation in demo (full functionality deferred for client deployment)

Management

  • Menu — comprehensive menu item management with category organization, item creation with name, description, price, and image, modifier groups for variants and add-ons, availability toggling (sold out temporarily), pricing history tracking, and menu export/import for backup
  • Inventory — stock management system where each menu item is linked to ingredients, automatic stock deduction when orders are placed, low stock alerts with configurable thresholds, supplier management with contact information, stock-in transactions for deliveries, stock adjustments for waste or spoilage, and inventory valuation reports
  • Staff — staff management with employee records including name, role, and contact information, shift scheduling with calendar view, attendance tracking, performance metrics (orders processed, average ticket value, tips received), and role-based access control determining which modules each staff member can access
  • Expenses — expense tracking with category-based organization (food cost, labor, utilities, rent, marketing), vendor management, expense approval workflows, budget vs actual variance reporting, and expense trend analysis over time
  • Reports / Analytics — comprehensive reporting suite with sales reports (daily, weekly, monthly, yearly), category performance analysis, item popularity ranking, staff productivity metrics, peak hour identification for staffing optimization, customer behavior analysis, and export capabilities in PDF and Excel formats
  • CRM / Guests — customer relationship management with customer profiles including contact information, visit history with order details, spending analytics (total spent, average visit value, visit frequency), loyalty tracking with points or rewards systems, special notes (allergies, preferences, VIP status), and marketing segmentation for targeted campaigns
  • Documents — document management system with file upload capability for contracts, certificates, and operational documents, document categorization and tagging, document versioning, and secure document sharing with staff

System

  • Intelligence — 15-module AI-assisted insights layer including floor operations insights (table turnover, seating efficiency), kitchen efficiency analysis (prep time, bottleneck identification), menu performance optimization (high-margin items, low performers), revenue trend forecasting, inventory optimization (stock-out prediction, overstock prevention), delivery analytics (delivery time, late order analysis), staff productivity metrics, reservation patterns, and purchasing recommendations based on demand forecasting
  • Workflows — configurable workflow builder allowing cafes to define custom automation rules (e.g., automatically notify kitchen when order is placed, automatically clear table after payment completion, automatically generate purchase order when stock falls below threshold), workflow executor that runs rules in real-time, and workflow templates for common operational patterns
  • Health monitoring — system health dashboard showing application performance metrics, device monitor tracking connected devices and their status, backup health monitoring with last backup timestamp and status, storage monitor showing disk usage and capacity, operational alerts for proactive issue detection (slow performance, storage running low, backup failures), and health history for trend analysis
  • Backup / Export — data export functionality supporting CSV for data portability, JSON for complete data backup, import wizard for restoring from backups, backup centre showing backup history and restore options, cloud provider integrations architected for AWS S3, Azure Blob Storage, Supabase, and WebDAV (deferred for client deployment), and scheduled backup configuration
  • Print — receipt generation system using jsPDF for professional receipt formatting, print queue for managing print jobs, printer routing for directing specific print jobs to specific printers (kitchen printer vs receipt printer), PDF export for digital receipts and reports, and customizable receipt templates with business logo and contact information
  • Settings — business profile configuration (name, address, contact info, logo), terminal configuration for multi-terminal setups, theme settings for visual customization, receipt and printing settings (printer selection, paper size, receipt content), tax configuration (GST rates, tax-inclusive vs tax-exclusive pricing), and system preferences
  • Notifications — activity feed showing all system events with timestamps, notification bell with unread count, operational inbox for action-required items, notification preferences per user (email, in-app, push), and notification history for audit and reference

Demo mode: Screenshots show the system with simulated data. Development Process

The project followed a modular development process with AI-assisted coding:

  • Requirements gathering: Studied real cafe operations across different types (coffee shop, quick-service, full-service cafe), interviewed cafe owners, baristas, and managers to understand pain points, documented workflows for ordering, kitchen operations, seating, delivery, and management
  • Architecture design: Designed a feature-module architecture with 25 self-contained modules, planned the Intelligence layer with 15 AI-assisted insight modules, designed the Workflows engine for automation, planned the health monitoring system, and decided which integrations to defer for client deployment
  • Incremental implementation: Built core operations first (Dashboard, POS, KDS, Tables), then management modules (Menu, Inventory, Staff, CRM, Expenses, Reports), then advanced features (Intelligence layer, Workflows, Health monitoring), then system infrastructure (Backup/Export, Print, Settings, Notifications), and finally polished UI and UX
  • AI-assisted development: Used Kiro for generating React components and refactoring code, Devin (formerly Windsurf) for debugging state synchronization issues and performance optimization, Antigravity for architectural decisions and module design, Trae for building UI components with Tailwind CSS, and Claude for documentation, problem-solving, and edge case handling
  • Testing and iteration: Tested each module with realistic cafe scenarios, simulated peak hour operations with multiple concurrent orders, tested real-time synchronization across modules, gathered feedback from cafe industry professionals, and iterated on the interface based on usability testing

Challenges & Lessons Learned

  • Module decoupling with shared state: Keeping 25 feature modules decoupled while sharing state (orders, tables, kitchen all need to stay in sync) required careful design of the data model and state management, learned that a centralized data model with clear ownership boundaries is essential for large systems
  • POS flow optimization: Designing a POS flow fast enough for real service staff required minimizing interactions to place an order, optimizing search for rapid item lookup, and designing keyboard shortcuts for power users, learned that every click in a high-traffic environment costs time and affects customer experience
  • Kitchen urgency logic: Kitchen display urgency logic determining when an order becomes Rush vs Active based on elapsed time and order type required configurable thresholds and clear visual indicators, learned that urgency algorithms need to be tunable per business type
  • Scope management for demo vs production: Understanding what to build now vs defer — separating demo-viable functionality from production requirements (cloud auth, real delivery APIs, shift reconciliation) — required disciplined decision-making, learned that deferring complex integrations for client deployment keeps the demo focused while ensuring production readiness through architecture and documentation
  • System expansion boundaries: Scope management — a system this large can expand indefinitely; learning to draw lines around what's needed for a working demo required defining MVP (Minimum Viable Product) clearly and resisting feature creep, learned that a complete working demo is better than an incomplete feature-rich system
  • Intelligence layer complexity: Building the 15-module AI-assisted insights layer required designing meaningful metrics that actually provide actionable insights rather than vanity metrics, learned that analytics should drive specific actions (staffing, inventory, menu optimization) rather than just display data
  • Workflows engine flexibility: Designing the configurable workflow builder and executor required balancing flexibility (users can create any workflow) with simplicity (not overwhelming users), learned that workflow templates and guided configuration improve adoption
