Clinic CRM — ClinOS

Full medical suite — React, TypeScript, Firebase, Recharts

← Back to Portfolio

Project Overview

ClinOS is a full-featured medical clinic management system built with React and TypeScript, backed by Firebase Firestore for real-time data synchronization and Firebase Auth for secure authentication. It covers the complete patient journey — from front-desk queue management and appointment scheduling through consultation documentation, prescriptions with dosage presets, lab orders and results tracking, billing with GST support, and multi-channel communications (SMS, Email, WhatsApp) — with an admin dashboard that surfaces critical alerts, overdue follow-ups, and priority actions in real time. The system includes AI-assisted patient profiles that surface key context and risk scores.

The system addresses key clinic pain points: fragmented patient data across different systems, manual queue management causing long wait times, prescription errors from lack of standardization, missed follow-ups leading to poor patient outcomes, lack of real-time visibility into clinic operations, and inefficient communication with patients.

Built with AI-assisted development using Kiro, Devin (formerly Windsurf), Antigravity, Trae, and Claude. Uses demonstration data only — no real patient information is stored or exposed. All patient names, IDs, and clinical data shown are simulated. My contribution involved defining healthcare workflows across all modules by studying real clinic operations, designing the data model and navigation structure, creating the AI-assisted patient profile system, implementing the queue management with real-time status tracking, testing functionality across different clinical scenarios, and iterating on the interface based on usability feedback.

Problem Statement

Medical clinics, especially small to mid-sized practices, operate with fragmented systems:

  • Patient data fragmentation: Patient records spread across paper files, spreadsheets, and different software systems, leading to incomplete histories and inability to see the full patient picture
  • Manual queue management: Queue tracking on paper or basic boards causes long wait times, no visibility into wait duration, and difficulty prioritizing urgent cases
  • Prescription errors: Lack of standardized prescription templates and dosage presets leads to medication errors, illegible handwriting, and inconsistent prescribing practices
  • Missed follow-ups: No systematic tracking of follow-up requirements leads to missed appointments, poor chronic disease management, and worse patient outcomes
  • Operational blind spots: Management cannot see real-time clinic status — how many patients waiting, how many in consultation, how many overdue for follow-up — without being physically present
  • Inefficient communication: Manual phone calls and paper reminders for appointments, lab results, and follow-ups are time-consuming and have low response rates

ClinOS was built to unify all clinic operations into a single system with real-time queue management, standardized clinical workflows, automated follow-up tracking, comprehensive patient profiles, and multi-channel patient communication.

Solution Approach

The solution uses a real-time architecture where Firebase Firestore stores all patient data and clinic operations with real-time synchronization across all devices. Key architectural decisions:

  • Real-time queue management: Queue status (Scheduled → Checked In → Waiting → With Doctor → Billing → Completed) updates instantly across all devices, allowing front desk, doctors, and billing to see the same patient flow
  • Patient-centric data model: All clinical data (consultations, prescriptions, lab orders, billing, communications) linked to patient records, creating complete patient history and timeline
  • Standardized clinical workflows: Prescription templates with dosage presets (OD/BD/TDS/QID/SOS), lab order templates with priority levels, and consultation note templates for consistency
  • AI-assisted patient profiles: AI-generated patient snapshots surfacing key context (last seen, key clinical notes, risk score) and readiness checklists for each visit
  • Role-based access control: Admin and Receptionist roles with different views and permissions, ensuring staff see only relevant information for their role
  • Multi-channel communications: Integrated SMS, Email, and WhatsApp with template library for appointment reminders, lab results, medication reminders, and follow-up calls
  • Demo mode with simulated data: All patient data is simulated (150 demo patients, 95 appointments, 24 overdue follow-ups) with clear demo mode indicators and no real patient information

Implemented Features

Clinical Operations

  • Admin Dashboard — live metrics showing today's appointments count, patients currently waiting, completed consultations, pending payments, and critical alerts, live queue/waiting room view with real-time patient status, follow-up centre with urgency indicators (overdue, due soon, upcoming), quick action buttons for common tasks (Add Patient, Book Appointment, Create Invoice, View Reports, Send Message), and drill-down capabilities for each metric
  • Queue & Front Desk — real-time patient flow tracking through 8 statuses (Scheduled → Checked In → Waiting → With Doctor → Billing → Completed), auto-refresh ensuring all devices show current status, walk-in check-in for immediate patient registration, call next patient action to advance queue, voice search for rapid patient lookup, and export queue to CSV for external reporting
  • Appointments — calendar view with monthly navigation showing all appointments, filter by doctor for multi-doctor clinics, filter by appointment type (consultation, follow-up, procedure), filter by date range for specific periods, overdue view showing missed appointments requiring follow-up, upcoming view for scheduling, 95 total appointments in demo, 24 follow-up overdue requiring attention, and appointment status tracking
  • Consultations & Encounters — patient consultation notes saved to patient timeline for complete history, draft templates for common consultation types, activity log showing all consultation-related actions, encounter documentation with chief complaint, history, examination, assessment, and plan, 150 total patients in demo, and consultation history per patient
  • Prescriptions — create prescriptions with multiple medications per prescription, dosage field with precise amount, frequency field with schedule, duration field with treatment length, quick-preset buttons for common patterns (OD - once daily, BD - twice daily, TDS - three times daily, QID - four times daily, SOS - as needed, Before food, After food), special instructions field for additional notes, refill request tracking, and prescription history per patient
  • Lab & Diagnostics — lab order creation with patient selection, test type selection from catalogue, priority levels (Routine for normal processing, Urgent for expedited, Stat for immediate), clinical notes for test context, results tracking when lab reports return, reporting by test type and priority, and export lab orders/results to CSV

Administration

  • Billing — invoice creation with line items for services and medications, tax rate presets (0%, 5%, 12%, 18% GST) for different service categories, discount application (percentage or flat amount), due date setting for payment terms, payment tracking across three tabs (Invoices for outstanding, Payments for received, Insurance for insurance claims), payment status tracking (pending, partial, paid, overdue), and export billing data to CSV
  • Communications — multi-channel communication supporting SMS, Email, and WhatsApp, quick template library for common messages (Appointment Reminder, Follow-up Call, Medication Reminder, Lab Results Ready, Payment Reminder), message scheduling for future delivery, call log for recording patient communications, automation rules for trigger-based communications, and communication history per patient
  • Reports & Analytics — patient statistics showing total patients (150 in demo), active patients (20), new registrations in period (150), status distribution chart visualizing patient categories, demographics breakdown (Male 54, Female 50, Other 46, average age 46), recent registrations table for quick review, specialized report tabs (Appointments analysis, Revenue tracking, Performance metrics, Follow-up compliance), and export reports to CSV/PDF
  • Documents — document management system with file upload capability for patient reports, scans, and certificates, document categorization (lab reports, imaging, insurance documents, consent forms), document versioning, and secure document sharing with patients
  • Staff — staff and doctor records with roles, permissions, contact information, and availability tracking
  • Settings & Audit — system configuration including clinic details, tax rates, appointment types, and audit trail showing all system actions with timestamps and user attribution

Patient Management

  • Patients list — 150 patients in demo with comprehensive records, sortable table with columns for ID, age, assigned doctor, status, insurance status, last visit date, risk alerts, and risk score, filter functionality by status/doctor/insurance/risk level, list view for detailed data, card view for visual summary, analytics view for population-level insights, duplicate detection algorithm flagging potential duplicate records (29 flagged in demo), and import/export for data migration
  • Patient profile — AI-generated snapshot showing last seen date, key clinical context, and risk indicators, quick action buttons for common tasks (Book Appointment, Start Consultation, New Prescription, Upload Report, Create Invoice, Call Patient, Schedule Follow-Up, Send Message), visit readiness checklist ensuring all requirements are met (phone verified, ID checked, consent signed, insurance verified, emergency contact recorded, documents uploaded), tabbed interface with Timeline (complete patient journey), Medical History (conditions, allergies, medications), Clinical Support (care plans), Documents (all patient files), Notes (internal notes), Follow-Up (scheduled follow-ups), Consents (signed consents), and Audit Log (all changes)
  • Role-based access — Admin role with full system access including settings and audit log, Receptionist role with front-desk operations access (queue, appointments, billing, communications) but restricted from clinical data, local demo mode with sample data for testing without configuration, and secure authentication with Firebase Auth

Data privacy: Demo mode only. All patient names, IDs, and clinical data shown are simulated. No real patient information is stored or processed. This is a demonstration system for portfolio purposes only.

Development Process

The project followed a structured development process with AI-assisted coding:

  • Requirements gathering: Studied real clinic operations across different types (single-doctor practice, multi-doctor clinic, specialty clinic), interviewed clinic administrators, doctors, and receptionists to understand pain points, documented workflows for patient intake, queue management, consultations, prescriptions, lab orders, billing, and communications
  • Architecture design: Chose Firebase Firestore for real-time data synchronization eliminating the need for custom WebSocket infrastructure, designed a patient-centric data model where all clinical data links to patient records, planned the queue management system with 8 status transitions, designed the AI-assisted patient profile system, and implemented role-based access control from the start
  • Incremental implementation: Built core data models first (patients, appointments, queue), then queue management with real-time status tracking, then appointments and calendar, then consultations and clinical documentation, then prescriptions with dosage presets, then lab orders and results, then billing with GST, then communications with templates, then analytics and reports, then AI-assisted patient profiles, and finally polished UI and UX
  • AI-assisted development: Used Kiro for generating React components and TypeScript interfaces, Devin (formerly Windsurf) for debugging real-time subscription issues and performance optimization, Antigravity for architectural decisions and database schema design, Trae for building UI components and styling, and Claude for documentation, problem-solving, and edge case handling
  • Testing and iteration: Tested each module with realistic clinic scenarios, simulated patient flow from registration through billing, tested real-time synchronization across multiple devices, validated prescription templates and dosage presets, tested communication templates and scheduling, gathered feedback from healthcare professionals, and iterated on the interface based on usability testing

Challenges & Lessons Learned

  • Queue system complexity: Designing a queue system that tracks patient state across 8 statuses (Scheduled → Checked In → Waiting → With Doctor → Billing → Completed) in real time across multiple browser sessions required careful state management and conflict resolution, learned that real-time queue systems need optimistic UI updates with rollback on conflict
  • Role-based access granularity: Role-based access — admin sees everything, receptionists see front-desk operations only, doctors see their own patients and consultations — required designing a flexible permission system that can express complex rules while maintaining security, learned that permissions should be enforced at both the UI and database level
  • Prescription design balance: Prescription design — balancing clinical flexibility (any medication, any frequency) with quick-entry presets that make common patterns fast — required designing a system that supports both free-form entry and template-based entry, learned that clinical tools need to accommodate both routine cases and edge cases
  • Patient risk scoring UX: Patient risk scoring — surfacing critical alerts without overwhelming the interface — required designing a graduated alert system (info, warning, critical) with contextual presentation, learned that clinical dashboards need to prioritize alerts without causing alert fatigue
  • Data privacy considerations: Building a clinic management system required careful consideration of data privacy even with demo data, learned to implement clear demo mode indicators, use simulated data exclusively, and document that no real patient information is processed
  • AI-assisted profile accuracy: Implementing AI-assisted patient profiles that surface key context required ensuring the AI-generated summaries are accurate and helpful rather than misleading, learned that AI features in healthcare need clear labeling of AI-generated content and human oversight
  • Communication template flexibility: Designing communication templates that work across SMS, Email, and WhatsApp required accounting for different character limits, formatting capabilities, and delivery reliability of each channel, learned that multi-channel communication needs channel-specific template variations
