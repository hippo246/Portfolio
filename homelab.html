2. Storage Architecture

My storage is organised across multiple drives with separate purposes for application data, media files, and network shares.

Storage Layout

  • NVMe Drive: Operating system and application installations
  • Additional SSD: Separate storage (capacity to be verified)
  • ~1 TB HDD: Media files, photos, and bulk storage

Directory Structure

  • Storage1: Contains directories including "immich", "media", and "photos"
  • Storage2: Contains "media2" directory with media folders including "Movies" and "Kdrama"
  • Ubuntu Share: Filesystem share for network access

Storage Philosophy: I keep drives separate rather than merging them into a single storage pool. This approach reduces the risk of data loss if a single drive fails, though it requires manual management of where data is stored.

Verification Needed: Immich photo storage configuration. The intention is to use the HDD for photo storage rather than the nearly full system SSD. Current mount configuration and actual data location need verification.

4. Networking & Remote Access

My networking setup prioritises private remote access through Tailscale rather than exposing services to the public internet.

Network Configuration

  • LAN Address (Current): 192.168.0.198
  • LAN Address (Previous): 192.168.100.195 (router change)
  • Tailscale IPv4: 100.72.219.81
  • Remote Access Method: Tailscale private VPN
  • Public Exposure: Services accessed privately, not exposed to public internet

Tailscale Usage

Tailscale provides private remote access to homelab services. This approach avoids exposing applications to the public internet and simplifies secure access from external devices.

Security Boundary: Services are accessed through Tailscale rather than public endpoints. This reduces the attack surface but does not replace proper service hardening or security best practices.

5. Firewall & Access Controls

UFW (Uncomplicated Firewall) is used to restrict unnecessary access while allowing required service connections.

UFW Configuration

  • Default Policy: Restrictive incoming and routed traffic defaults
  • Tailscale Rules: Rules configured to allow Tailscale-related traffic
  • Docker-to-Collabora: Firewall rule investigated/configured for Collabora CODE connectivity

Security Approach: The firewall follows a principle of restricting unnecessary access while allowing required connections through specific rules. Services remain reachable through intended paths (LAN or Tailscale).

Important: Docker networking can create additional network interfaces that may bypass UFW rules depending on configuration. This environment has not undergone a professional security audit.

6. SMB/CIFS Network Shares

Configured persistent SMB mounts from ThinkPad to homelab storage shares (Storage1, Storage2, Ubuntu share) using /etc/fstab entries with network-aware options (_netdev, nofail, x-systemd.automount) to handle boot-time network availability. Updated SMB configuration after LAN subnet change to reference the new server address (192.168.0.198).

11. Lessons Learned & Future Improvements

Key technical insights from practical work and areas for continued development.

Key Lessons

  • Storage Strategy: Keeping drives separate reduces single-point-of-failure risk but requires manual management of data placement
  • Network Renumbering: Using stable identifiers (hostnames, DNS, VPN) rather than hardcoded IPs makes infrastructure more resilient to changes
  • Firewall Complexity: Docker networking can bypass host firewall rules; understanding container networking is essential for security
  • Service Upgrades: Application upgrades require attention to configuration changes, port mappings, and data migration
  • Hardware Investigation: Tools like rdmsr, /proc/cpuinfo, and sensors provide insight into low-level system behaviour
  • Unresolved Issues: Not every problem has an immediate solution; documenting the investigation process is still valuable
  • Security Boundaries: Private VPN access (Tailscale) reduces public exposure but does not replace service hardening
