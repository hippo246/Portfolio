Restaurant Management System

Full-stack restaurant operations platform — React, Vite, Supabase

← Back to Portfolio

Project Overview

RestoCRM is a comprehensive restaurant management system built with React 19 and Vite 8, backed by Supabase for real-time data synchronization using PostgreSQL and WebSocket-based subscriptions. It covers the complete restaurant workflow — from customer QR self-ordering at the table through to POS operations for staff, kitchen display systems for chefs, table management for hosts, reservation booking for front desk, delivery management for takeout, and advanced analytics for management. The system is designed for commercial deployment with client provisioning workflows, licensing system documentation, support access management, client deployment processes, and update workflows for production environments.

The system addresses key restaurant pain points: disconnected POS and kitchen systems leading to order errors, manual table tracking causing seating inefficiencies, lack of real-time order visibility for customers, fragmented reservation systems, no centralized inventory tracking across ordering channels, and inability to scale to multiple locations with consistent operations.

Built with AI-assisted development using Kiro, Devin (formerly Windsurf), Antigravity, Trae, and Claude. My contribution involved defining restaurant workflow requirements across all modules by studying real restaurant operations, designing the data model and user flows for each operational area, creating the kitchen routing engine with station-based item assignment, implementing the complete print infrastructure with ESC/POS thermal printer support, building the multi-branch architecture for scalability, designing the role-based permission system, creating the tax engine for GST calculation, testing functionality across different restaurant scenarios, and iterating on the interface based on usability feedback.

Problem Statement

Restaurants, especially those scaling from single to multiple locations, face operational fragmentation:

  • Order inaccuracies: Orders taken on POS don't always match what kitchen prepares due to manual communication gaps, leading to wrong dishes and food waste
  • Inefficient seating: Hosts manage tables manually with paper or basic tools, causing double-bookings, long wait times, and poor table turnover
  • Customer disconnect: Customers have no visibility into order status after placing it, leading to repeated "is my food ready?" questions frustrating both customers and staff
  • Reservation chaos: Reservations tracked in separate systems or on paper, leading to overbooking, no-shows, and poor capacity planning
  • Inventory blind spots: No connection between ordering channels (dine-in, delivery, QR) and inventory, leading to stock-outs during service and food waste from over-preparation
  • Scaling challenges: Opening a second location means duplicating systems manually, with no centralized management, consistent reporting, or unified operations

RestoCRM was built to unify all restaurant operations into a single real-time system where an order placed via QR immediately shows on the kitchen display, table status updates in real-time across all devices, and management has complete visibility into all locations from a single dashboard.

Solution Approach & System Architecture

The solution uses a real-time event-driven architecture where Supabase PostgreSQL stores relational data and WebSocket subscriptions push updates instantly to all connected kitchen, POS, and floor devices without polling.

  • Supabase real-time backend: All data lives in PostgreSQL with Supabase Realtime subscriptions, ensuring that an order placed on a customer's phone immediately appears on the kitchen display without polling.
  • Station-based kitchen routing: Menu items are assigned to kitchen stations (grill, fry, prep, bar, etc.), and the kitchen engine automatically routes orders to the appropriate stations based on item configuration.
  • Multi-branch architecture: Each restaurant branch has isolated data with a branch switching system, allowing management to view and manage multiple locations from a single interface.
  • Custom state management: Built a custom useStore hook with localStorage persistence and cloud sync, keeping dependencies minimal.
  • Print infrastructure: Complete printing system supporting browser-based printing for invoices and ESC/POS commands for thermal printers via network, WebUSB, or Bluetooth.
  • Tax engine: Handles CGST/SGST by category with configurable rates, calculating taxes automatically at order time.

Implemented Features

Point of Sale

  • POS Express — streamlined 3-step checkout for high-volume fast service: step 1 select items from categorized menu, step 2 review order with subtotal and tax, step 3 select payment method and complete. Designed for cafes and quick-service restaurants where speed is critical.
  • POS Pro — full-featured POS for full-service restaurants with modifier selection (add-ons, substitutions, special requests), split bill functionality (by item, by percentage, by seat), delivery support with address entry and zone-based pricing, automatic tax calculation (CGST/SGST by category), discount application (percentage or flat), and advanced order management with hold, recall, and void capabilities.
  • Split Bill — flexible bill splitting system supporting three modes: split by item (each person pays for specific items), split by percentage (equal percentage splits like 50/50 or 33/33/33), and split by custom amount (manual entry per person). Automatically recalculates taxes and totals for each split.
  • Modifier Picker — modal interface for selecting menu variants and modifiers, supporting nested modifier groups (e.g., "choose one" + "choose any"), price adjustments for premium options, and special request text fields for custom instructions.
  • Kitchen Pickup Display — customer-facing screen showing order status (pending, preparing, ready, served) with order numbers and estimated wait times, designed for display on tablets or TVs near the pickup counter.

Kitchen Operations

  • Kitchen Display System (KDS) — comprehensive KDS with tabbed interface for different views (all orders, by station, by table), bump mode to clear completed orders with keyboard shortcuts, station-based order routing, color-coded order cards with heat indicators (cold/warm/hot based on elapsed time), rush status badges for VIP or time-sensitive orders, and order completion workflow with chef acknowledgment.
  • Kitchen Order Cards — individual order cards displaying table number, order time, elapsed time with color-coded urgency, complete item list with quantities, dietary flags (vegetarian, vegan, gluten-free, allergens), special requests highlighted, preparation stage indicators (new, in progress, ready, served), and fire/call waiter action buttons.
  • Kitchen Engine — pure JavaScript calculation engine (no React dependencies) that performs heat analysis based on elapsed time and order type, rush detection using configurable thresholds, stage transitions (new → preparing → ready → served), allergen cross-contamination warnings, and kitchen analytics (average prep time, bottleneck identification, station load balancing).
  • Station Routing — automatic routing system where menu items are assigned to kitchen stations (grill, fry station, cold prep, bar, dessert, etc.) in the menu configuration, and the kitchen engine groups items by station and displays them on the appropriate KDS tab, enabling chefs to focus only on their station's orders.

Print Infrastructure

  • Browser Print — browser window-based printing system for customer invoices, kitchen tickets (itemized by station), and delivery labels, using CSS print media queries for consistent formatting across browsers and devices.
  • ESC/POS Support — ESC/POS command builder implementing thermal printer commands including text formatting (bold, underline, double-height), barcode printing (QR codes, Code 128), cut commands, cash drawer kick, and image printing for logos, compatible with most Epson, Star, and USB thermal printers.
  • Receipt Builders — modular line builders for different receipt types: customer receipts with itemized bill, tax breakdown, and payment info; kitchen tickets with station-separated items and preparation notes; delivery labels with address, contact info, and order summary; all with configurable headers, footers, and formatting.
  • Printer Manager — thermal printer connection manager supporting network printers (via HTTP/WebSocket), USB printers (via WebUSB API), and Bluetooth printers (via WebBluetooth API), with connection state monitoring, automatic reconnection, error handling, and a sendToThermal function that accepts ESC/POS commands and handles encoding and transmission.
  • Takeaway Labels — label generation system for takeaway orders with customer name, order number, item summary, special dietary flags, preparation time, and QR code for order tracking, including a preview modal and customizable label settings (size, font, logo inclusion).

Front of House

  • Dashboard — management dashboard showing live revenue (today, week, month), active order counts, table status overview (available, occupied, reserved), key performance metrics (average order value, table turnover rate), pending reservations count, and quick action buttons for common tasks.
  • Tables — visual floor plan editor with drag-and-drop table positioning, real-time table status updates across all devices (available → seated → dirty → cleaning), merge tables functionality for large parties, split tables for separating checks, duration tracking to identify long-seated tables, and per-table order access.
  • Reservations — reservation booking system with calendar view, time slot configuration with capacity limits, customer contact information, special requests, reservation status tracking (confirmed, seated, cancelled, no-show), automated reminders, and waitlist management for overbooked periods.
  • Live Order Board — real-time order status display using Supabase Realtime subscriptions, showing all active orders across the restaurant with table numbers, elapsed time, status indicators, and kitchen completion status, updated instantly without page refresh or polling.
  • QR Ordering — customer-facing QR code menu where scanning a table QR code opens a mobile-optimized menu, customers browse items with images and descriptions, add items to cart, specify special requests, and place orders assigned to their table, with guest session management that persists across page refreshes without requiring login.
  • Combo Manager — combo meal and bundle creation system allowing restaurants to define fixed-price combinations (e.g., "Lunch Combo: Burger + Fries + Drink"), pricing rules (fixed price or component-based pricing), and component substitutions, with automatic combo breakdown in kitchen tickets.

Management

  • Menu — comprehensive menu management with category organization, item creation with images, descriptions, and pricing, modifier groups with nested options, variant support (size options, flavor choices), availability toggling (sold out temporarily), and pricing history tracking.
  • Inventory — stock tracking system where each menu item is linked to ingredients, automatic stock deduction when orders are placed, low stock alerts with reorder thresholds, supplier management with contact information, stock-in transactions for deliveries, stock adjustments for waste or theft, and inventory valuation reports.
  • Staff — staff management with employee records, shift scheduling with calendar view, attendance tracking, performance metrics (orders processed, average ticket value, tips received), role-based access control with the permission system, and productivity dashboards comparing staff performance.
  • Customers (CRM) — customer relationship management with contact information and profiles, visit history with order details, spending analytics (total spent, average visit value, visit frequency), loyalty tracking with points or rewards systems, special notes (allergies, preferences, VIP status), and marketing segmentation.
  • Deliveries — delivery order management with address entry and validation, zone-based pricing (different delivery fees by distance), delivery driver assignment, delivery status tracking (confirmed, preparing, out for delivery, delivered), proof of delivery (signature or photo), and delivery performance analytics (average delivery time, late deliveries).
  • Expenses — expense tracking with category-based organization (food cost, labor, utilities, rent, marketing), vendor management, expense approval workflows, budget vs actual variance reporting, and expense trend analysis over time with visualization.
  • Wastage — waste logging system with reason codes (expired, spoiled, preparation error, customer return, theft), cost impact calculation, waste reduction reporting with trend lines, root cause analysis to identify problem areas, and waste percentage tracking as a KPI.
  • Analytics — comprehensive analytics suite with sales trends (daily, weekly, monthly, yearly), category performance analysis (which menu categories drive revenue), peak hour identification for staffing optimization, staff productivity metrics, customer behavior analysis (frequency, average spend), profitability analysis (margin by item and category), and exportable reports in PDF and Excel formats.

System & Infrastructure

  • Multi-Branch Support — branch switching interface allowing management to view and manage multiple restaurant locations, branch-specific data isolation ensuring each location's data stays separate, centralized reporting across all branches, and branch configuration (address, contact info, tax rates, business hours).
  • Authentication — secure login system using Web Crypto API for PBKDF2 password hashing (no plaintext passwords), session management with configurable timeout, secure session storage, password reset functionality, and failed login attempt monitoring with lockout thresholds.
  • Role-Based Permissions — fine-grained permission system with five core roles (Admin with full access, Manager with operational access, Staff with order-taking access, Kitchen with KDS access only, Cashier with payment access only), each role has specific tab access, widget visibility, and action permissions, with custom role creation capability for specialized needs.
  • Theme System — customizable theme system with token-based color palette, support for light and dark modes, brand color customization for each restaurant branch, theme persistence across sessions, and consistent styling across all components using CSS custom properties.
  • Export System — data export functionality supporting CSV for data portability, PDF for formatted reports and invoices, Excel with multiple sheets for complex reports, scheduled exports for backup purposes, and export templates for consistent formatting.
  • Activity Log — comprehensive audit trail logging all system actions including who performed the action, what was changed, when it happened, and from which device, with filtering and search capabilities for compliance and debugging.
  • Notifications — in-app notification system with real-time alerts for new orders, order status changes, low stock warnings, and reservation confirmations, browser push notification support for staff when away from the app, notification history, and notification preferences per user.
  • Tax Engine — tax calculation engine supporting GST with CGST/SGST split, category-based tax rates (e.g., food at 5%, beverages at 12%, service charges at 18%), automatic tax calculation at order time, tax-inclusive and tax-exclusive pricing modes, and tax reporting by category and period.
  • Profit Helpers — profitability calculation utilities including margin calculation per item (selling price minus cost of goods sold), gross margin analysis by category, cost analysis by ingredient, food cost percentage tracking, and profitability reports highlighting high-margin and low-margin items.

Commercial Readiness: Phase 13 (Commercial Readiness) completed. The system includes demo deployment guides for production environments, client provisioning workflows for onboarding new restaurant locations, licensing system documentation for commercial distribution, support access management for customer support teams, client deployment processes for smooth handovers, domains and certificates configuration for custom URLs, customer dashboard for internal support operations, and update workflows for rolling out new features to existing clients without downtime.

Technology Stack

  • Frontend: React 19, Vite 8
  • Backend / Database: Supabase (PostgreSQL, Auth, Realtime subscriptions)
  • State Management: Custom useStore hook with localStorage + cloudStorage fallback
  • Routing: React Router DOM
  • QR Codes: qrcode, qrcode.react
  • Testing: Vitest
  • Styling: Custom global CSS with theme token system
  • Security: Web Crypto API for password hashing (PBKDF2)

Development Process

The project followed a structured development process with AI-assisted coding:

  • Requirements gathering: Studied real restaurant operations across different types (cafe, quick-service, full-service), interviewed restaurant owners, managers, chefs, and servers to understand pain points, documented workflows for ordering, kitchen operations, seating, reservations, and delivery
  • Architecture design: Chose Supabase for real-time data synchronization eliminating the need for custom WebSocket infrastructure, designed a tab-based module architecture for maintainability, planned the kitchen routing engine early to avoid refactoring menu structure, decided on custom state management to keep bundle size small
  • Incremental implementation: Built core POS first (order creation, cart, checkout), then kitchen display with station routing, then front-of-house features (tables, reservations, QR ordering), then management features (menu, inventory, staff, analytics), then advanced features (print infrastructure, multi-branch, permissions), and finally commercial readiness features (licensing, provisioning, updates)
  • AI-assisted development: Used Kiro for generating React components and refactoring code, Devin (formerly Windsurf) for debugging real-time subscription issues and performance optimization, Antigravity for architectural decisions and database schema design, Trae for building UI components and styling, and Claude for documentation, problem-solving, and edge case handling
  • Testing and iteration: Tested each module with realistic restaurant scenarios, simulated peak hour operations with multiple concurrent orders, tested real-time synchronization across multiple devices and browsers, validated print output on actual thermal printers, gathered feedback from restaurant industry professionals, and iterated on the interface based on usability testing

Challenges & Lessons Learned

  • Supabase Realtime complexity: Using Supabase Realtime for the Live Order Board required handling connection drops gracefully, implementing reconnection logic, managing subscription lifecycle to prevent memory leaks, and ensuring optimistic UI updates that rollback on error — learned that real-time systems need robust error handling and fallback mechanisms
  • QR ordering session management: Designing the QR ordering flow so customers can browse, order, and track without needing an account while maintaining session state across page refreshes required a custom guest session system using localStorage with expiry, learned that guest sessions need to be stateless from the server side but stateful on the client for smooth UX
  • Custom state management trade-offs: Keeping table state consistent across the floor plan, live order board, and kitchen simultaneously with a custom state management system instead of Redux or Zustand required careful design of the useStore hook and pub/sub patterns, learned that custom solutions work well for specific use cases but require more initial design work than off-the-shelf solutions
  • Kitchen routing engine complexity: Building a kitchen routing engine that automatically assigns items to stations based on menu configuration while handling special requests and dietary flags required separating business logic from UI, learned that pure calculation engines (no React dependencies) are easier to test and maintain
  • Browser API limitations for printing: Implementing ESC/POS thermal printer support across network, USB, and Bluetooth connections revealed browser API limitations (WebUSB and WebBluetooth have limited browser support), learned to provide browser-based printing as fallback and document printer compatibility clearly
  • Multi-branch data isolation: Designing a multi-branch architecture that isolates data per branch while allowing branch switching without data leakage required careful database schema design with branch_id on all records, learned that data isolation must be enforced at both the database level (row-level security) and application level (UI filtering)
  • Permission system granularity: Creating a role-based permission system that works across tabs, widgets, and actions while maintaining security required designing a flexible permission matrix that can express complex rules, learned that permissions should be defined declaratively and enforced consistently throughout the application
  • Commercial readiness scope: Building commercial readiness features like client provisioning, licensing, and update workflows for production deployments expanded the scope significantly beyond core functionality, learned that commercial features should be planned from the start rather than added as an afterthought
